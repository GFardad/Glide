## 1) Exact file:line mismatches

### 1.1 `types/index.ts:1-6` — Plan-specified interfaces replaced with string type aliases
**Plan** (TechnicalSpec.md §Core Type Contracts): `AgentId`, `SessionId`, `ToolName` are interfaces with `readonly id: string` / `readonly name: string`.
**Code:** `type AgentId = string`, `type SessionId = string`, `type CampaignId = string` — no `readonly` branding, no object wrapping.

### 1.2 `types/index.ts:27-48` — `Agent` interface diverges from Plan's `AgentContext`
**Plan** specifies `AgentContext` with path-based fields: `personalityPath`, `goalPath`, `notesPath`, `todoPath`, `rejectedPath`, `sessionPath`, plus `tokenBudget: number` and `allowedMcp: string[]`.
**Code** defines `Agent` with inline content fields (`personality`, `goal`, `notes`, `todos`, `rejected`) and **no** `tokenBudget`, **no** `allowedMcp`, **no** path fields. The Plan's `AgentContext` interface is entirely absent.

### 1.3 `types/index.ts` — `ToolName` interface missing
**Plan** (TechnicalSpec.md:47-49): `export interface ToolName { readonly name: string }`
**Code:** No `ToolName` exists anywhere in core.

### 1.4 `types/index.ts` — `ToolCall` interface missing
**Plan** (TechnicalSpec.md:66-70): `export interface ToolCall<T = unknown> { name: ToolName; arguments: Record<string, unknown>; accessLevel: "cto" | "agent" }`
**Code:** Absent entirely.

### 1.5 `types/index.ts` — `MeetingRoomOutput` interface missing
**Plan** (TechnicalSpec.md:72-78): `export interface MeetingRoomOutput { riskLog: string[]; architecture: string[]; todoRegistry: TodoItem[]; driftScore: number; decision: "approved" | "revise" | "rejected" }`
**Code:** Absent entirely.

### 1.6 `types/index.ts` — `TodoItem` interface missing
**Plan** (TechnicalSpec.md:80-86): `export interface TodoItem { id: string; title: string; owner: AgentId; status: "pending" | "in_progress" | "done" | "rejected"; priority: number }`
**Code:** Absent entirely. `Agent.todos` uses `string[]` instead.

### 1.7 `constitution.ts:107` — `JSON.parse` without schema validation
**Plan** requires "schema-first design" and "type-level validation".
**Code:** `return JSON.parse(readFileSync(path, "utf8")) as Constitution` — raw parse with type assertion, no Zod.

### 1.8 `campaign/index.ts:43` — Same raw `JSON.parse` without validation
`return JSON.parse(readFileSync(path, "utf8")) as Campaign` — same pattern as 1.7.

### 1.9 `constitution.ts:236-240` and `campaign/index.ts:52-53` — Declared dependencies unused
`package.json:14` declares `"ulid": "^2.3.0"` and `"nanoid": "^5.0.0"`.
**Code:** Both files use `Date.now().toString(36) + Math.random().toString(36).slice(2, 8)` for ID generation.
**Plan** (Architecture.md §6.3): `ulid / nanoid — تولید ID session/agent`.

### 1.10 `constitution.ts:97-98` — Side-effect imports placed mid-file
`readFileSync`, `writeFileSync`, `existsSync`, `mkdirSync`, `join` are imported at lines 97-98, after 96 lines of interface/class definitions. Standard convention: imports at the top.

### 1.11 `constitution.ts:107` and `campaign/index.ts:43` — `Date` fields become `string` after deserialization
`Campaign.createdAt`, `Campaign.updatedAt`, `Constitution.createdAt`, `Constitution.updatedAt`, `ConstitutionAmendment.proposedAt` are typed as `Date` in interfaces, but `JSON.parse` returns strings. The type contract is silently broken.

### 1.12 `constitution.ts:236-240` — `Math.random()` for IDs
`generateAmendmentId()` uses `Math.random()` — not collision-resistant, not ordered, not time-sortable. Plan specifies ULIDs for this purpose.

### 1.13 `campaign/index.ts:26-34` — `formatMarkdown` joins array with `\n` without bullet/header structure
`formatMarkdown("Non-Goals", nonGoals.join("\n"))` produces flat text. Plan's `NON_GOALS.md` and `ASSUMPTIONS.md` should use a list format (e.g., `- item` per line) for readability.

### 1.14 `index.ts:1-5` — `.js` extensions in ESM barrel re-exports
All re-exports use `.js` extensions (`"./types/index.js"`). This is a TypeScript source tree; extensionless or `.ts` imports are standard for intra-package references.

### 1.15 `goal.ts:1` — Status vocabulary doesn't share base with TodoItem statuses
Plan's `TodoItem.status` = `"pending" | "in_progress" | "done" | "rejected"`.
Code's `GoalStatus` = `"active" | "scheduled" | "completed" | "abandoned"`.
No shared status union exists; downstream consumers cannot relate goals to todos.

## 2) Non-production-grade patterns found

### 2.1 Zero Zod usage despite Zod declared as a dependency
`package.json:13` lists `"zod": "^3.23.0"`. Zero files in `src/` import Zod. The Plan explicitly mandates schema-first validation. Every `JSON.parse` + `as` cast is a violation.

### 2.2 Non-atomic file writes
- `constitution.ts:114-120` — `writeFileSync` directly overwrites `constitution.json`. A crash during write leaves a truncated/corrupted file.
- `campaign/index.ts:24-34` — Writes `campaign.json`, then `GOAL.md`, then `NON_GOALS.md`, then `ASSUMPTIONS.md` sequentially. No atomicity guarantee across the four files.

### 2.3 Unvalidated error thrown for malformed data
`campaign/index.ts:40-43` throws `CampaignNotFoundError` for missing files but throws a raw `Error` for corrupt JSON. No `InvalidCampaignError` or `InvalidConstitutionError` exists.

### 2.4 `GlideError` lacks error cause chain
`errors/index.ts:1-8` — `GlideError` captures `(message, code)` but not the underlying `cause`. Modern production-grade errors implement `Error.cause` for diagnostic chaining.

### 2.5 `Campaign.agentId` in `Artifact` uses `AgentId` (string alias) but Agent has no ID field
`Artifact.agentId: AgentId | null` references the `AgentId` type alias, but the `Agent` interface has `id: AgentId` and no `AgentId` branded type exists. This is loosely coupled but the Plan intended `AgentId` to be a branded type.

### 2.6 `GoalRecord.metadata` uses `Record<string, unknown>`
`goal.ts:19` — `metadata?: Record<string, unknown>`. The Plan explicitly calls out `Record<string, unknown>` as a "vibe-coded" anti-pattern that must be replaced with a proper Zod schema.

### 2.7 No fsync/durability guarantees
All `writeFileSync` calls in `constitution.ts` and `campaign/index.ts` lack `fsync` or any durability guarantee. On power loss or OOM kill, data is lost.

### 2.8 `PermissionDeniedError` never raised
`errors/index.ts:17-24` defines `PermissionDeniedError` but no code in core raises it. Dead code in the public API surface.

### 2.9 No `README.md` public API completeness
`README.md` lists 4 public API items but the actual exports include 5 interfaces (Campaign, Agent, Artifact, Principle, Constitution, ConstitutionAmendment, BackwardsCompatibilityAssessment, GoalRecord), 6 error classes, and 8 functions. The README is incomplete.

Either align the code to the Plan or update the Plan to reflect a deliberate simplification — but the current silent divergence is unacceptable.

**F2. Replace all `JSON.parse + as` with Zod schemas** (`types/index.ts`, `constitution.ts`, `campaign/index.ts`)
```ts
import { z } from "zod";

const CampaignSchema = z.object({
  id: z.string(),
  root: z.string(),
  goal: z.string(),
  nonGoals: z.array(z.string()),
  assumptions: z.array(z.string()),
  createdAt: z.coerce.date(),
  updatedAt: z.coerce.date(),
});
export type Campaign = z.infer<typeof CampaignSchema>;
```
Same pattern for `Constitution`, `ConstitutionAmendment`, `Principle`, `GoalRecord`.

**F3. Use `ulid` / `nanoid` for ID generation** (`constitution.ts:236-240`, `campaign/index.ts:52-53`)
```ts
import { nanoid } from "nanoid";
function generateCampaignId(): CampaignId { return `camp_${nanoid()}`; }
```

**F4. Fix Date deserialization** (all `load*` functions)
After Zod `coerce.date()`, `Date` fields are properly deserialized. Until then, explicitly `new Date(...)` after parsing.

**F5. Make file writes atomic** (`constitution.ts:114-120`, `campaign/index.ts:24-34`)
```ts
import { renameSync, unlinkSync } from "node:fs";
function atomicWrite(path: string, content: string): void {
  const tmp = `${path}.tmp-${process.pid}`;
  writeFileSync(tmp, content);
  renameSync(tmp, path); // atomic on POSIX
}
```

**F6. Add `InvalidCampaignError` and `InvalidConstitutionError`** (`errors/index.ts`)
Replace raw `throw new Error(...)` with typed subclasses for all data-validation failures.

## Summary

| Dimension | Finding |
|-----------|---------|
| **Plan alignment** | 5 Plan-specified interfaces (`AgentContext`, `ToolName`, `ToolCall`, `MeetingRoomOutput`, `TodoItem`) are **entirely absent** from core. Plan's `AgentId`/`SessionId` are interfaces in the Plan but type aliases in code. |
| **Schema validation** | Zero Zod usage despite Zod being a declared dependency and the Plan mandating schema-first design. All data loading uses raw `JSON.parse + as` casts. |
| **ID generation** | `ulid` and `nanoid` are declared dependencies but never imported. Both `constitution.ts` and `campaign/index.ts` use `Math.random()`-based IDs. |
| **Durability** | All file writes are non-atomic. No `fsync`, no temp-file + rename pattern. Crash = data corruption. |
| **Date handling** | `Date` fields in interfaces silently become `string` after `JSON.parse`, breaking the type contract at runtime. |
| **Tests** | **Zero tests exist.** `vitest run` returns nothing. This violates all four plan documents' quality gates. |
| **Error handling** | `CampaignNotFoundError` is used, but corrupt data throws a raw `Error`. No `InvalidCampaignError`. `GlideError` lacks `cause`. `PermissionDeniedError` is dead code. |
| **Code quality** | Side-effect imports mid-file (`constitution.ts:97-98`), `.js` extensions in barrel (`index.ts`), `Record<string, unknown>` in `GoalRecord.metadata`. |
| **Positive findings** | Interfaces are well-documented with JSDoc. Type names are consistent. Package structure is clean (6 files, clear separation). `tsconfig.json` extends the base config correctly. No circular dependencies. |

**Bottom line:** `packages/core` has a clean structural skeleton but is a **stub implementation** — it declares the right package role in the Plan but ships no Plan-specified types, no schema validation, no test coverage, no durable I/O, and unused declared dependencies. It requires the P0 fixes (F1-F6) before it can be considered production-grade.
